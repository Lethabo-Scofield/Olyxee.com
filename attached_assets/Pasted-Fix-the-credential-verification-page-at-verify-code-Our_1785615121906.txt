Fix the credential verification page at /verify/[code]

Our admin system (a separate app at admin.olyxee.com) issues internship credentials. Each certificate has a QR code pointing to https://olyxee.com/verify/<code>, where <code> looks like:

OLX-CERT-2026-0001-egI9dN_lGB6U

The page currently shows "No credential found" for valid codes. Rebuild it to work like this:

Step 1 — Extract the secure token from the code. The token is the part after OLX-CERT-YYYY-NNNN-. Important: the token itself can contain dashes and underscores, so never use split("-"). Use this exact regex:

const token = code.match(/^OLX-CERT-\d{4}-\d{4}-(.+)$/)?.[1] ?? "";

Step 2 — Fetch the credential from the admin API. It's a public, read-only, no-auth endpoint (CORS already allows olyxee.com and www.olyxee.com; server-side fetch also works):

GET https://admin.olyxee.com/api/public/credentials/<token>

Do not cache the response (cache: "no-store").

Step 3 — Render based on the response:

HTTP 200 with verified: true — show the full credential. Fields available: credentialNumber, fullName, programmeTitle, position, department, startDate, completionDate, issueDate, projectsCompleted, responsibilities, skillsDemonstrated, publicRecommendation, supervisorName, founderName, founderTitle, founderRecommendation, managerName, managerTitle, managerRecommendation, and documents (which document types exist). Display it as an official verification: "✓ Verified — this credential was issued by Olyxee (Pty) Ltd", with the person's name, programme, dates, and the write-ups. projectsCompleted and responsibilities are newline-separated — render each line as a bullet.
HTTP 200 with verified: false — the credential exists but was revoked or expired (status is "REVOKED" or "EXPIRED"). Show a clear notice with the credentialNumber, e.g. "This credential has been revoked and is no longer valid."
HTTP 404 — show "No credential found. Check the URL or contact Olyxee."
If the regex in Step 1 matches nothing, treat it the same as 404 without calling the API.
Test with a real example: publish nothing new — just take the code from any issued certificate PDF (bottom-left, "Certificate Number") and open /verify/<that code>. It must show the full details.

One note: because your only published certificate was regenerated today, its QR is current — but the displayed result depends entirely on the marketing site making the API call above. Once that page is fixed, scanning the QR will show the full credential on olyxee.com.
