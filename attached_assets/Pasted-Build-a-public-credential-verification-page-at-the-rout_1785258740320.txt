Build a public credential verification page at the route /verify/[slug].

How it gets opened: Interns' certificates carry a QR code that encodes a URL like https://olyxee.com/verify/OLX-CERT-2026-0001-AbCdEf123456. The slug is the credential number plus a random verification token; the token is everything after the last hyphen (AbCdEf123456 in the example).

How to fetch the data: Extract the token from the slug and call the admin API (server-side, so there are no CORS concerns): GET https://admin.olyxee.com/api/public/credentials/{token}

Possible responses:

404 with { "verified": false, "status": "NOT_FOUND" } → invalid/unknown credential
200 with { "verified": false, "status": "REVOKED", "credentialNumber": "..." } → revoked credential
200 verified:
{
  "verified": true,
  "status": "PUBLISHED",
  "credentialNumber": "OLX-CERT-2026-0001",
  "fullName": "Jane Doe",
  "programmeTitle": "Olyxee Software Engineering Internship",
  "position": "SE Intern",
  "startDate": "2026-07-01",
  "completionDate": "2026-08-31",
  "projectsCompleted": "…",
  "skillsDemonstrated": "…",
  "publicRecommendation": "…",
  "supervisorName": "…",
  "issueDate": "2026-08-31",
  "issuer": { "name": "Olyxee", "website": "https://olyxee.com" }
}

Page design — three states:

Verified (certificate view): A clean, formal certificate-style page matching olyxee.com branding. At top, a prominent green "✓ Verified Credential" badge with the credential number. Then: intern's full name (largest text), programme title, position, internship period (start → completion dates), issue date. Below, sections for "Projects Completed" and "Skills Demonstrated" (render as lists if comma/line separated), and a quoted recommendation block with the supervisor's name. Footer: "Issued by Olyxee" linking to olyxee.com, and a note that this page is the authoritative verification record. Add a "Share" / copy-link button.
Revoked: A red/amber banner: "This credential (OLX-CERT-…) has been revoked and is no longer valid." Show no personal details.
Not found: Neutral message: "No credential matches this verification code. Check the URL or contact Olyxee." Show no details.
Requirements:

Fetch server-side (SSR) so the result is crawlable and fast; send Cache-Control: no-store — never cache verification results.
Mobile-first: most visitors arrive by scanning a QR code on a phone.
Set page <title> to "Verified: {fullName} — {programmeTitle} | Olyxee" for verified credentials; generic titles for the other states.
Handle API downtime gracefully ("Verification is temporarily unavailable, try again shortly") — never show a raw error.
No authentication, no cookies, no tracking of the token in analytics URLs.
Two things to adjust on your side:

Replace admin.olyxee.com in the prompt with wherever this admin app is actually hosted (its Vercel domain).
If you'd rather query the Supabase database directly instead of the API, read from the intern_credentials table joined with interns, looking up by verification_token — but only select the public fields listed above, and only treat status = 'PUBLISHED' as verified. The API route is still the safer option since that filtering is already done for you.
